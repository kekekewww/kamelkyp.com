### 4.1 (a) One shared "fetcher settled" primitive

#### 4.1.1 Pure tracker: `app/components/studio/ui/fetcher-settle.ts` (new)

This follows the repo split of a pure module plus a hook (`editor-state.ts` + `use-editor-form.ts`, R5). It has no
React import, so node unit tests can drive it.

```ts
/**
 * Fetcher lifecycle tracking (admin-architecture §4.6–4.8). Router state
 * updates are transitions: when rendering is slow, React can skip the
 * "submitting"/"loading" renders and go straight from idle to idle with new
 * data (227faa1). A submission has therefore finished when the fetcher is idle
 * and either a busy state was observed or its data is new.
 */
export type FetcherPhase = "idle" | "submitting" | "loading";
export type FetcherEvent = "start" | "settled" | null;

export interface SettleTracker {
  /** State seen on the previous observation. */
  state: FetcherPhase;
  /** Data already reported (or present at mount): never reported again. */
  handled: unknown;
}

export function createSettleTracker(state: FetcherPhase, data: unknown): SettleTracker {
  return { state, handled: data };
}

/** Advances `tracker` (mutates it) and says what this observation means. */
export function observeFetcher(
  tracker: SettleTracker,
  state: FetcherPhase,
  data: unknown,
): FetcherEvent {
  const previous = tracker.state;
  tracker.state = state;
  if (state !== "idle") return previous === "idle" ? "start" : null;
  if (previous === "idle" && data === tracker.handled) return null;
  tracker.handled = data;
  return "settled";
}
```

Semantics (each one is a unit test, §6.1):

| Observed sequence | Events |
| --- | --- |
| idle(A) → submitting → loading → idle(B) | `start`, —, `settled` |
| idle(A) → idle(B) (**busy renders skipped**) | `settled` (the old rule emitted nothing) |
| idle(A) → loading → idle(B) (submitting skipped) | `start`, `settled` |
| mount idle(A), re-render idle(A) | — |
| idle(B) settled, then idle(B) again | — (never twice) |
| idle(A) → idle(B) → idle(C) | `settled`, `settled` |
| idle(A) → submitting → idle(A) (no new data) | `start`, `settled`. This keeps today's behaviour (227faa1 also counts an observed busy state). |

#### 4.1.2 Hook: `app/components/studio/ui/use-fetcher-settled.ts` (new)

```ts
import { useEffect, useRef } from "react";
import { createSettleTracker, type FetcherPhase, observeFetcher } from "./fetcher-settle";

type FetcherLike<D> = { state: FetcherPhase; data: D | undefined };

/**
 * Calls `onStart` when a submission leaves idle and `onSettled` exactly once
 * per finished submission, even when React skipped the busy renders. Handlers
 * are read from a ref (latest closure), like `useProjectSubmit`.
 */
export function useFetcherSettled<D>(
  fetcher: FetcherLike<D>,
  handlers: { onStart?: () => void; onSettled: (data: D | undefined) => void },
): void {
  // Only the first render's value is kept (like `useRef(fetcher.state)` in
  // use-project-submit); later allocations are discarded.
  const tracker = useRef(createSettleTracker(fetcher.state, fetcher.data));
  const latest = useRef(handlers);
  latest.current = handlers;
  useEffect(() => {
    const event = observeFetcher(tracker.current, fetcher.state, fetcher.data);
    if (event === "start") latest.current.onStart?.();
    else if (event === "settled") latest.current.onSettled(fetcher.data);
  }, [fetcher.state, fetcher.data]);
}
```

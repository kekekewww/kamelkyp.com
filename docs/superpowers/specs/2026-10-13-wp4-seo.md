## 1. Goal

Give the public site its missing search and sharing basics and keep everything private out of search:

1. `GET /robots.txt`. It is dynamic. On the production origin it disallows the private surfaces and points to the
   sitemap. On every other deployment (PR previews, loopback, dev) it disallows everything.
2. `GET /sitemap.xml`. It is dynamic and lists only published, listed public pages, in every locale where each
   page renders. It includes `xhtml:link` hreflang alternates and uses the configured origin (`APP_ORIGIN`).
3. Head tags on every public page: `<link rel="canonical">`, hreflang alternates for `/zh` and `/en`
   (plus `x-default`), `og:url`, and an absolute `og:image` that falls back to a static Kamel-branded default.
4. A web app manifest (`/manifest.webmanifest`) and static icons (favicon, apple-touch-icon, manifest icons).
5. Noindex rules: preview deployments are noindex at the response-header level. Unlisted entries, commission
   workflow pages and error pages carry `<meta name="robots" content="noindex">`. Studio, preview and API
   surfaces stay noindex and are disallowed in `robots.txt`.
6. Coverage: unit tests for builders and meta, worker tests for D1-backed sitemap data and the resource routes,
   loopback e2e for served head tags, sitemap and robots, and a Studio e2e that ties publish/unlist to the
   sitemap.

Out of scope: per-project generated OG images (a follow-up named in
`docs/superpowers/specs/2026-09-23-editorial-redesign-design.md:132`), `Product`/`Offer` structured data (it
would put prices in a second place; see §4.11), Search Console verification (an owner operation, listed in the
runbook only), RSS, and any service worker or PWA installability.

## 4. Design

### 4.1 Indexing policy (one table, enforced by tests)

| Surface | HTTP status | `X-Robots-Tag` | `<meta name="robots">` | canonical + hreflang | In sitemap |
| --- | --- | --- | --- | --- | --- |
| Static public pages (§4.6 list), both locales | 200 | — | — | yes | yes |
| `/:lang/works/:slug`, `/:lang/writing/:slug`: published, listed, rendered in that locale | 200 | — | — | yes (hreflang only for locales it renders in) | yes |
| Same, **unlisted** (`listed = 0` in the published snapshot) | 200 | — | `noindex` | no | no (owner decision O1) |
| `/:lang/mixing/{full,vocal}`, `/:lang/song-transition/{simple,edit}` | 200 if the service row is published, else 404 | — | — | yes | only when published and visible in that locale |
| `/:lang/commission` (landing) | 200 | — | — | yes | yes |
| `/:lang/commission/:category`, `/:lang/commission/:category/:service`, `/:lang/commission/success` | 200 | — | `noindex` | no | no |
| `/:lang/other[/:slug]` | 301 | — | — | — | no |
| `/:lang/works?category=x` | 200 | — | — | canonical = `/:lang/works` (R5) | the bare path only |
| 404 / 500 (root `ErrorBoundary`) | 404/500 | — | `noindex` | no | no |
| `/studio/**`, `/api/studio/**` | 403 without Access | `noindex, nofollow` (existing) | — | no | no; `Disallow: /studio`, `/api/` |
| `/studio/preview/**` | 403 without Access | `noindex, nofollow` (existing) | `noindex,nofollow` (existing) | no | no |
| `/admin/**`, `/api/**`, `/language/**` | 403 / JSON / 302 | — | — | — | no; disallowed |
| `/robots.txt`, `/sitemap.xml` | 200 (sitemap 503 on D1 failure) | — | — | — | — |
| **Any response on a non-indexable request** (preview deployment, loopback, dev, or a non-canonical host of production) | as above | `noindex, nofollow` on every Worker response | unchanged | unchanged | robots.txt is `Disallow: /` |

Deployment-level noindex is expressed **only** in the `X-Robots-Tag` header and `robots.txt`, never in head
tags. The served HTML is therefore identical in structure on preview and production (only the origin differs).
Loopback e2e can assert canonical, hreflang and OG exactly as production will serve them, and
`tests/e2e/work.spec.ts:116` stays valid.

### 4.4 URL helpers (`app/lib/seo/urls.ts`, new, client-safe)

```ts
import { LOCALES, type Locale } from "../i18n/locale";

export interface PublicSeoContext { origin: string }        // layout loader data
export const HREFLANG: Record<Locale, string> = { zh: "zh-Hant", en: "en" }; // = <html lang>
export const X_DEFAULT_LOCALE: Locale = "en";               // = negotiation fallback (locale-cookie.server.ts:22)

/** Strip a trailing slash (except "/"), never a query or hash. "/en/works/" → "/en/works". */
export function canonicalPath(pathname: string): string;
export function absoluteUrl(origin: string, path: string): string;   // origin + path

/**
 * hreflang set for a /zh|/en path. Empty when fewer than two locales render
 * (a one-locale page gets no alternates). Order: LOCALES order, then x-default.
 * Uses switchLocalePath (app/lib/i18n/path.ts:8).
 */
export function localeAlternates(
  origin: string,
  pathname: string,
  locales: readonly Locale[],
): Array<{ hrefLang: string; href: string }>;
```

`hrefLang` is camelCase on purpose. React Router spreads meta descriptor props into `createElement("link")`,
and React renders `hrefLang` as the `hreflang` attribute.

### 4.5 Head tags (`app/lib/cms/public/meta.ts`, modify)

**Signatures.**

```ts
export interface PageMeta {
  title?: string | null;            // omitted on the home page only (existing semantics, :32)
  description?: string | null;
  image?: PublicImage | null;
  noindex?: boolean;
  type?: "website" | "article";
  /** Locales this page renders in; default both (static pages). */
  locales?: readonly Locale[];
}

type MetaInput = {
  matches: ReadonlyArray<{ id: string; loaderData?: unknown }>;
  location: { pathname: string };
};

export function seoFromMatches(matches: MetaInput["matches"]): PublicSeoContext | null; // "routes/public/layout" only
export function pageMeta(args: MetaInput, page: PageMeta): MetaDescriptor[];               // was (matches, page)
export function publicMeta(
  input: PageMeta & { site: PublicSiteContext; seo?: (PublicSeoContext & { pathname: string }) | null },
): MetaDescriptor[];
```

`pageMeta` uses `location.pathname` and not a match's `pathname`. A route that inherits the layout meta would
otherwise get the layout's path ("/en") as its canonical. `previewMeta` is unchanged.

**Tag order** (deterministic; `tags[0]` stays the title):

1. `{ title }` (unchanged rule: home = `siteTitle`, else `"<page> — <brandName>"`).
2. `description` (unchanged).
3. If `noindex`: `{ name: "robots", content: "noindex" }`.
4. If `seo` and not `noindex`:
   - `{ tagName: "link", rel: "canonical", href: origin + canonicalPath(pathname) }`.
   - The `localeAlternates(...)` results as `{ tagName: "link", rel: "alternate", hrefLang, href }`.
5. `og:title`, `og:site_name`, `og:type`, `og:locale` (unchanged).
   - Then `og:locale:alternate` for each other locale in `locales`, when `seo` is present and not `noindex`.
   - Then `og:url` (= canonical) when `seo` and not `noindex`.
   - Then `og:description`.
6. Image, with this precedence (aligned with the Studio hints, R13):
   - home (`!title`): `page.image ?? site.ogImage ?? site.defaultSocialImage`
   - other pages: `page.image ?? site.defaultSocialImage ?? site.ogImage`
   - then, when `seo` is present, the static default `DEFAULT_OG_IMAGE` (§4.10) as `absoluteUrl(origin, path)`.
   Emit `og:image`, `og:image:width`/`og:image:height`, `og:image:type` (static default only) and `og:image:alt`
   (asset alt, or the localized default alt).
   - Width and height are emitted for the static default, and for a media image **only when its `src` is the
     original file** (`!image.srcSet` and both dimensions known). With image transformations on, `src` is a
     `/cdn-cgi/image/width=<n>` variant (`app/lib/cms/media/urls.ts:94–107`) while `width`/`height` are the
     original's, so emitting them would declare the wrong size.
7. `twitter:card`: `summary_large_image` when an image was emitted, else `summary`.
8. JSON-LD `WebSite`: unchanged fields, plus `url: origin + "/" + locale` when `seo` is present. There is still
   no `Person`, no `author` and no email.
9. Icons:
   - brand favicon link (existing, :105–112) when `site.brand.favicon` is set
   - else `{ tagName: "link", rel: "icon", href: "/icons/icon-32.png", type: "image/png", sizes: "32x32" }`
   - then always `{ tagName: "link", rel: "apple-touch-icon", href: "/apple-touch-icon.png" }` and
     `{ tagName: "link", rel: "manifest", href: "/manifest.webmanifest" }`.

Without `seo` (unit tests, a layout render without Cloudflare context) there is no canonical, no alternate
link, no `og:locale:alternate`, no `og:url`, no JSON-LD `url` and no default image. The icon/manifest links
(step 9) and the image precedence (step 6) apply with or without `seo`. The existing `public-meta.test.ts` cases
(:20–142) still pass unchanged: the favicon case uses `toContainEqual`, the image case sets only `ogImage` (so
both precedences pick it), and no new tag contains `Person` or `author`. The layout-meta case in
`tests/unit/service-pages.test.tsx:133–145` passes no `location` and no `seo`, and must keep passing (the layout
meta reads `location` only when `loaderData.seo` is set).

### 4.6 Data flow

```
request ─► workers/app.ts ─► RR handler
             │                 ├─ /robots.txt   → routes/robots.ts   → buildRobotsTxt({indexable, origin})
             │                 ├─ /sitemap.xml  → routes/sitemap.ts  → listSitemapEntries(DB) → buildSitemapXml(entries, origin)
             │                 └─ /:lang/*      → public/layout loader → { locale, site, seo: { origin } }
             │                                     └─ leaf meta → pageMeta({matches, location}, page) → head tags
             └─ headers: buildSecurityHeaders({ …, indexable: isIndexableRequest(env, url) })
static (asset layer, Worker not invoked): /manifest.webmanifest, /favicon.ico, /apple-touch-icon.png,
                                          /icons/*.png, /og/kamel-default.png
```

**Layout loader** (`app/routes/public/layout.tsx`): returns `{ locale, site, seo }` (update the explicit return
type at :37).
- Order: the locale check (:38–40); then `if (!provider) return { locale, site: fallbackSiteContext(null, locale),
  seo: null }` **without touching `request`** (the unit test at `tests/unit/service-pages.test.tsx:108–121` calls
  the loader with `{ params }` only); then `seo = { origin: siteOrigin(env, request.url) }` **before** the D1
  `try`, so the D1 fallback path still emits canonical tags.
- The layout `meta` becomes
  `({ loaderData, location }) => loaderData?.site ? publicMeta({ site, seo: loaderData.seo ? { ...loaderData.seo, pathname: location.pathname } : null }) : []`.

### 4.7 Sitemap read (`app/lib/cms/public/sitemap.server.ts`, new)

```ts
export interface SitemapEntry {        // declared in app/lib/seo/sitemap.ts
  path: string;                        // locale-less: "", "/works/fixture-signal-map"
  locales: readonly Locale[];          // locales in which the path renders 200
  lastModified: string | null;         // ISO timestamp (row.published_at) or null
}

export async function listSitemapEntries(db: D1Database): Promise<SitemapEntry[]>;
```

The function reuses `readEntities` (`read.server.ts:37–84`, published mode) and the existing visibility
predicates. There is no view context, no asset reads and no price reads.

1. **Static:** `SITEMAP_STATIC_PATHS` → `{ path, locales: LOCALES, lastModified: null }`.
2. **Commission service pages:**
   - Read `readEntities(db, "service", "published", { where: "t.commission_service_id IS NOT NULL AND t.todo_content = 0" })`.
   - Keep rows whose `content.commissionServiceId` passes `isServiceId`.
   - `path = commissionServicePath(id)`, `locales = LOCALES.filter((l) => isServiceVisible(content, l))`,
     `lastModified = row.published_at`. Order: `SERVICE_CATALOG` order.
3. **Projects:**
   - Read `readEntities(db, "project", "published", { where: "t.todo_content = 0" })`.
   - Keep `content.listed === true` — the **snapshot** value, not the `t.listed` working column (R12).

### 4.8 Sitemap and robots output (`app/lib/seo/sitemap.ts`, `app/lib/seo/robots.ts`, new, pure)

`buildSitemapXml(entries, origin)` writes one `<url>` per (entry, locale), in entry order and then `LOCALES`
order, with two-space indentation:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9" xmlns:xhtml="http://www.w3.org/1999/xhtml">
  <url>
    <loc>https://kamelkyp.com/zh/works/fixture-signal-map</loc>
    <lastmod>2026-09-20T00:00:00Z</lastmod>
    <xhtml:link rel="alternate" hreflang="zh-Hant" href="https://kamelkyp.com/zh/works/fixture-signal-map"/>
    <xhtml:link rel="alternate" hreflang="en" href="https://kamelkyp.com/en/works/fixture-signal-map"/>
    <xhtml:link rel="alternate" hreflang="x-default" href="https://kamelkyp.com/en/works/fixture-signal-map"/>
  </url>
</urlset>
```

- The home path `""` becomes `/zh` and `/en`.
- `<lastmod>` appears only when known. Alternates come from `localeAlternates` (§4.4), so a one-locale entry
  has none.
- Every text and attribute value goes through `xmlEscape` (`& < > " '`). There is no `changefreq` and no
  `priority`. One urlset is enough: the site is far below 50,000 URLs.

`buildRobotsTxt({ indexable, origin })`, exact output, with `\n` line endings and a trailing newline:

```
# indexable (production origin)
User-agent: *
Disallow: /admin
Disallow: /api/
Disallow: /language/
Disallow: /studio

Sitemap: https://kamelkyp.com/sitemap.xml
```

```
# not indexable (every other deployment)
User-agent: *
Disallow: /
```

The `# …` lines above label the two cases and are not part of the output. Commission workflow paths are **not**
disallowed: crawlers must be able to fetch them to see their `noindex`.

**Source form of the rules (cross-WP constraint).** `app/lib/seo/robots.ts` holds the indexable rules as whole
lines, `ROBOTS_INDEXABLE_LINES = ["User-agent: *", "Disallow: /admin", "Disallow: /api/", "Disallow: /language/",
"Disallow: /studio"]`, never as bare path literals such as a quoted `/admin`. WP5's
`tests/unit/admin-retirement-audit.test.ts` (WP5 spec §6.1) fails on any string literal that **starts with**
`/admin` in `app/**` outside its allowlist (WP5's four files plus WP3's `app/lib/cms/schemas/footer.ts`, plan §2.6).
WP5 strips comments before that check, but the plan's static gates (§2.6) still keep quoted `/admin` paths out of
comments.
`"Disallow: /admin"` does not match its regex, so WP4 needs no change to WP5's allowlist, whichever lands first.
The same rule applies to every other new `app/**` file in this WP: comments name the admin surface without
quoting a path that starts with `/admin`.

## 9. Owner decisions

- **O1. Unlisted published entries** (`listed = 0`, projects and writing). The docs say only "reachable by URL
  but omitted from lists and home" (content-schema.md:61); they do not say whether search engines should index
  them.
  - **Default in this spec:** they render normally, carry `<meta name="robots" content="noindex">`, and are
    excluded from the sitemap (the YouTube-style "unlisted" meaning).
  - **Alternative:** keep them indexable and only exclude them from the sitemap. This matches legacy behaviour:
    before the Studio, unlisted D1 works rendered with no robots meta (only file-based placeholders were
    `noindex`, `git show cc8df41^:app/routes/public/work-detail.tsx`, meta at :52–68).
  - Either way the sitemap excludes them. The decision affects §4.1, the two detail `meta` calls, two Studio
    hints and the `listed` line added to content-schema.md (§5).
  - The spec can be implemented with the default; flipping it later is a small, self-contained change.

Nothing else is open: the origin, locales, x-default (the negotiation fallback `en`), preview noindex, Studio
and API exclusion and the asset approach all follow from the cited docs and code. This WP introduces no price
values.

## 10. Acceptance criteria

- [ ] `GET /robots.txt` returns exactly the indexable text on `https://kamelkyp.com` with production
      `APP_ORIGIN`, and `User-agent: *\nDisallow: /\n` everywhere else, including `*.workers.dev` hosts of the
      production Worker. It never touches D1.
- [ ] `GET /sitemap.xml` returns valid sitemap XML with `xhtml` alternates.
  - It lists every static public path in both locales, published commission service pages, and published
    **listed** projects and internal writing in exactly the locales where they render.
  - It lists no draft, archived, unpublished, unlisted, external-only, TODO_CONTENT/`sample-`, Studio, API,
    admin or commission-workflow URL.
  - `<loc>` uses `APP_ORIGIN`. A D1 failure gives 503 with `Retry-After`.
- [ ] Every indexable public page has an absolute canonical (no query string, no trailing slash) and a matching
      `og:url`. `/:lang/works?category=x` canonicalizes to `/:lang/works`.
